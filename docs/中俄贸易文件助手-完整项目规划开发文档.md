# 中俄贸易文件助手｜完整项目规划与开发路线文档

> 项目代号：`rus-trade-file-assistant`  
> 产品定位：面向中俄贸易操作员的本地文件翻译、整理、核对和资料生成工作台  
> 文档范围：从第一版 Excel 翻译工具到最终完整桌面版本  
> 核心原则：本地优先、数据可控、人工可审核、逐步扩展、不替代专业合规判断  
> 文档关系：本文描述长期路线；V1 范围、验收和实现决策以《中俄贸易文件助手-项目初始化与第一版启动文档》及《项目决策记录》为准。

---

## 1. 产品愿景

建设一款面向中俄贸易操作人员的本地桌面工具，将分散在 Excel、Word、PDF、图片和压缩包中的文件处理工作统一到一个工作台中。

最终形成以下闭环：

```text
文件收集
→ 自动分类
→ 翻译与术语统一
→ 字段提取
→ 跨文件一致性核对
→ 缺失文件检查
→ 人工审核
→ 模板生成
→ 资料打包
→ 本地归档和检索
```

产品不以替代 ERP、报关系统、银行系统或法律合规人员为目标，而是填补这些系统之间大量依赖人工处理的文件操作环节。

## 2. 目标用户

### 2.1 中俄贸易操作员

主要任务：

- 处理询价、合同、发票和装箱单；
- 翻译俄文问题反馈；
- 整理报关和清关资料；
- 检查单证字段一致性；
- 跟踪缺失文件；
- 向客户、供应商、货代和报关行发送资料。

### 2.2 物流操作员

主要任务：

- 整理箱号、封号和运单；
- 处理铁路、公路、海运和空运文件；
- 汇总运输异常；
- 核对件数、重量和目的地；
- 生成运输资料包。

### 2.3 单证人员

主要任务：

- 制作商业发票、装箱单和形式发票；
- 检查合同与发票字段；
- 检查签章、日期、金额和证书；
- 管理文件版本。

### 2.4 业务负责人

主要任务：

- 查看订单文件完成度；
- 查看高风险差异；
- 查看待确认和超时事项；
- 复核最终资料包。

- 翻译引擎接口预留；在线翻译或本地模型须经独立决策后启用。

## 6. 最终用户工作流

## 6.1 文件收件箱

1. 用户拖入多个文件或文件夹；
2. 系统计算文件哈希；
3. 识别重复文件；
4. 初步识别文件类型；
5. 提取订单号、合同号等候选字段；
6. 推荐归属订单；
7. 推荐文件名；
8. 用户确认；
9. 系统复制或移动到工作区；
10. 保留原始来源信息。

## 6.2 文件翻译

1. 识别语言；
2. 识别文档结构；
3. 应用保护规则；
4. 应用术语库；
5. 调用离线或在线翻译器；
6. 生成译文；
7. 做数量和格式校验；
8. 进入人工审核；
9. 保存翻译记忆；
10. 导出目标文件。

## 6.3 跨文件核对

1. 用户选择订单或多份文件；
2. 系统识别文件类型；
3. 提取字段；
4. 标准化字段；
5. 建立字段关系；
6. 执行规则；
7. 输出差异；
8. 用户确认正确值；
9. 生成核对报告；
10. 将确认结果用于后续模板生成。

## 6.4 资料打包

1. 用户选择资料包规则；
2. 系统检查缺失文件；
3. 检查当前版本；
4. 检查是否包含内部敏感文件；
5. 检查是否需要隐藏价格或供应商信息；
6. 生成目录；
7. 统一文件名；
8. 导出 ZIP；
9. 记录导出时间和文件列表。

## 8.4 字段提取模块

每个字段需要保存：

```ts
interface ExtractedField {
  id: string
  documentId: string
  fieldType: string
  rawValue: string
  normalizedValue?: string
  confidence: number
  page?: number
  sheet?: string
  cell?: string
  boundingBox?: BoundingBox
  sourceMethod: 'rule' | 'template' | 'model' | 'manual'
  reviewStatus: 'unreviewed' | 'confirmed' | 'corrected' | 'ignored'

```

提取策略：

1. 固定模板规则；
2. 关键词和位置规则；
3. 表格结构规则；
4. 业务词典；
5. 模型结构化提取；
6. 人工确认。

优先使用确定性规则，模型只补充复杂版式。

- 产品名称；
- 单位；
- 日期；
- 币种；
- 金额；
- 重量；
- 国家和城市；

## 19. 主要风险与应对

## 19.1 Excel 样式兼容

风险：

- 字号异常；
- 合并单元格错位；
- 图表或对象丢失；
- 公式变化。

应对：

- 第一版限制格式；
- 原文件只读；
- 临时文件验证；
- 固定回归样本；
- 对复杂文件提示风险。

## 19.2 翻译质量

风险：

- 专业词错误；
- 编号被改；
- 输出错位；
- 模型扩写。

应对：

- 术语库；
- 占位符保护；
- 数量校验；
- 人工审核；
- 翻译记忆；
- 不确定结果标记。

## 19.3 OCR 不稳定

风险：

- 印章、扫描倾斜、低清晰度；
- 表格结构错乱；
- 俄文字符误识别。

应对：

- 页面预处理；
- 置信度；
- 区域审核；
- 不直接用于高风险自动结论；
- 提示重新扫描。

## 19.4 字段提取误报

风险：

- 同一字段多处出现；
- 文件模板差异大；
- 模型将无关内容当字段。

应对：

- 原文定位；
- 多策略交叉；
- 置信度；
- 人工确认；
- 文档模板配置。

## 19.5 项目范围膨胀

风险：

- 过早加入 ERP、审批、移动端和云协作；
- 每个客户都增加专属规则。

应对：

- 版本边界；
- 插件和配置机制；
- 新需求必须进入优先级评审；
- 不破坏核心通用流程。

## 19.6 本地模型部署

风险：

- 安装包过大；
- 内存不足；
- 推理速度慢；
- 驱动差异；
- 模型许可问题。

应对：

- 模型独立下载；
- 能力检测；
- 多档模型；
- 可卸载；
- 在线模式可选回退；
- 明确许可证和来源。

## 19.7 本地任务数据与 IPC 协议

风险：

- Worker、桌面端和数据库多方直接读写，导致锁冲突、迁移失败或数据状态不一致；
- 长任务进度、取消、恢复和协议升级没有稳定契约，导致前后端耦合和难以回归测试；
- 任务恢复需要保存原文和译文，而日志或缓存可能意外泄露敏感业务信息。

应对：

- 每个阶段明确数据库和文件操作的唯一写入方；
- JSON Lines 消息包含协议版本、请求 ID、消息类型和稳定错误码，标准输出不得混入调试文本；
- 任务数据、缓存和日志分开留存与清理，日志默认脱敏；
- 协议与数据迁移均纳入自动化测试。

特别不建议在以下基础能力未稳定前开发跨文件核对：

- 文件类型识别；
- 字段定义；
- 文件版本；
- 原文定位；
- 人工确认；
- 样本回归。

## 24. 最终版本定义

最终版本应达到：

1. Windows 本地桌面运行；
2. 常见核心流程可完全离线；
3. 支持 Excel、Word、PDF 和图片；
4. 支持俄中翻译和术语统一；
5. 支持文件分类和批量整理；
6. 支持订单文件清单；
7. 支持关键字段提取；
8. 支持合同、发票、装箱单等跨文件核对；
9. 支持风险分级和原文定位；
10. 支持人工审核；
11. 支持模板和资料包生成；
12. 支持版本管理、检索、备份和审计；
13. 文件和业务数据默认不离开本机；
14. 高风险业务结论不得完全自动化；
15. 产品可通过插件和规则继续扩展。

最终产品定位：

> 一款本地优先、可离线运行、面向中俄贸易操作人员的双语文件翻译、整理、核对和资料生成工作台。
