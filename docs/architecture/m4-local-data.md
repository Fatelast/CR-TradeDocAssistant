# 中俄贸易文件助手｜M4 本地数据知识快照

> 完成版本：`0.5.0`  
> 完成日期：2026-07-31  
> SQLite schema：`3`  
> Worker 协议：`1.0`（向后兼容扩展）

## 1. 阶段结论

M4 已将 M1—M3 的单次翻译工作流扩展为可长期维护的完全离线桌面工作台。应用现在包含工作台、任务历史、术语与缓存、设置与维护四个模块；没有引入路由、全局状态库、在线翻译、账户或云端服务。

核心闭环：

```text
M1—M3 工作台
  ├─ 创建/恢复任务
  ├─ 审核并安全导出
  └─ 写入导出审计
        ↓
M4 本地数据层
  ├─ 历史查询 / 可信打开 / 重新执行 / 终态删除
  ├─ 术语 XLSX 原子导入导出
  ├─ 精确缓存查询和清理
  └─ 设置、日志轮转与固定保留策略
```

## 3. 数据模型

### `tasks.rerun_of_task_id`

重新执行不修改旧任务，而是重新读取源文件并创建新任务。新任务保存父任务 ID；源文件缺失、变化或缺少指纹时返回 `TASK_SOURCE_RESELECT_REQUIRED`。

### `task_exports`

每次导出独立记录：

- `pending`：写文件前已登记；
- `completed`：临时文件保存、重开逐格验证、最终落盘和 SHA-256 完成；
- `recovered`：启动时发现已落盘的遗留 `pending` 输出；
- `failed`：写入失败或遗留输出不存在。

历史删除级联任务行和导出记录，但不删除源文件或输出 Excel。

### `glossary_terms.term_key`

术语唯一性由规范化俄文、精确匹配、大小写选项的 SHA-256 决定。schema v2 的重复历史术语会保留，首条使用规范键，其余使用带旧 ID 的兼容键，避免迁移丢数据。

### `app_settings`

单行强类型设置：默认输出目录、批次大小 1～200、日志级别 `info/error`。固定保留期限不允许修改。

## 4. 文件与权限边界

- Renderer 不能直接访问文件系统、SQLite 或子进程；
- 工作簿和术语导入路径来自原生打开对话框；
- Excel、术语和设置导出路径来自原生另存为对话框；
- 默认输出目录只能沿用当前值、清空或采用本次原生目录选择结果；
- 历史文件打开只提交任务/导出记录 ID，真实路径由 Worker 从数据库解析；
- Worker 拒绝覆盖原文件和已有文件；
- 术语内容禁止以 `=` 注入 Excel 公式；
- 当前没有任何网络翻译或业务数据上传代码。

## 5. 清理一致性

固定保留策略：

- 完成/中止任务：90 天；
- 精确缓存：180 天；
- 应用日志：30 天。

应用启动时数据库自动清理最多每 24 小时一次，日志按启动检查。手动清理分为“预览”和“确认执行”：

1. Worker 选出精确任务 ID 和缓存键；
2. `planHash` 同时包含任务更新时间、导出记录修订和缓存修订；
3. Main 对过期日志按文件名、修改时间和大小生成独立哈希；
4. 预览后任何变化都会返回 `CLEANUP_PLAN_CHANGED`；
5. 清理范围永远不包含业务 Excel。

## 6. 术语 XLSX 契约

固定表头：

| 俄文原文 | 中文译文 | 分类 | 精确匹配 | 区分大小写 | 启用 | 备注 |
|---|---|---|---|---|---|---|

限制为 `.xlsx`、5 MiB、5,000 条。导入先检查模板、布尔值、公式、文件内重复和 SHA-256，再在单个事务中应用；一次导入最多递增一次术语版本。导出包含停用项，经临时保存和重新打开验证后落盘。

## 8. 下一阶段注意事项

M5 进入打包与真实文件内测时必须保留以下边界：

1. 打包后的 Worker 数据目录仍由 Main 注入，不允许 Renderer 指定；
2. 安装包升级必须对真实 schema v2/v3 数据副本做迁移回归；
3. Windows 安装/卸载不能默认删除 `userData/data` 或业务 Excel；
4. 真实文件回归继续覆盖高风险对象、文件锁、非 ASCII 路径和 Office/WPS 打开；
5. 在线翻译、SQLite 整库恢复和云同步仍属于延后决策，不能在 M5 顺带接入。
