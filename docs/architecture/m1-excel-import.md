# 中俄贸易文件助手｜M1 Excel 导入知识快照

## 阶段结论

M1 已完成从本地 `.xlsx` 到稳定业务数据行的只读闭环，不包含翻译、持久化或写回：

```text
选择或拖入文件
→ Main 校验扩展名并创建活动工作簿会话
→ Worker 预检 ZIP 与 Excel 风险
→ 识别工作表、有效区域和表头候选
→ 用户确认工作表、表头行和列映射
→ 生成带 Excel 行号与单元格坐标的数据行
```

## 核心实现

- Electron Main 持有唯一活动工作簿路径和临时 `workbookId`；
- Preload 使用白名单 API，拖入文件通过 Electron `webUtils.getPathForFile()` 获取路径；
- Python Worker 使用 `openpyxl` 的 `read_only=True`、`data_only=False`、`keep_links=False`；
- 有效区域按非空单元格扫描，不信任可能缺失或被格式污染的工作表尺寸元数据；
- 表头在前 12 行内评分并给出候选，用户可手动修正；
- 预览最多返回表头后的 12 行，避免将整张表传给 Renderer；
- 数据行只收集原文列非空记录，保留 `rowId`、Excel 行号、原文/目标/箱号单元格坐标。

## 默认边界

| 项目 | M1 默认值 |
|---|---:|
| 文件格式 | 仅 `.xlsx` |
| 单文件大小 | 10 MiB |
| 单工作表有效行数 | 5,000 |
| 单工作表有效列数 | 200 |
| 表头扫描范围 | 前 12 行 |
| 数据预览范围 | 表头后最多 12 行 |
| 活动工作簿 | 1 个 |

超限不会部分读取，而是返回稳定错误码并停止导入。

## 风险分级

- `notice`：合并单元格、公式、隐藏工作表。允许继续只读映射，但必须向用户展示原因；
- `restricted`：外部链接、图表、绘图对象、数据验证、条件格式。M1 允许只读预览，M3 禁止导出且不提供强制绕过；
- 加密工作簿、ZIP 条目超过 5,000 或解压后超过 200 MiB：直接拒绝。

公式使用公式文本展示，不在 Worker 中计算。M1 不保存、不修复、不覆盖原工作簿。

## 固定回归样本

- `resources/samples/m1-standard.xlsx`：第二行表头、合并单元格、冻结窗格、公式、已有译文与空译文混合；
- `resources/samples/m1-risky.xlsx`：数据验证和条件格式；
- `resources/samples/m1-over-limit.xlsx`：第 5,001 行包含有效数据。

所有样本均为脱敏构造数据，不得以真实客户文件替代后直接提交仓库。

## 验证结果（2026-07-30）

- Python Worker：9 项单元/协议测试通过；
- Electron WorkerClient：2 项跨进程 JSON Lines 测试通过；
- `npm run typecheck`、`npm run lint`、`npm run build` 通过；
- 真实 Electron 窗口导入标准样例，正确识别第二行表头、A/C/D 列，并生成 C3—C7 共 5 条稳定映射；
- 真实 Electron 窗口导入高风险样例，正确显示“受限预览”及数据验证、条件格式两条原因。

## M2 继续开发时的约束

- 不得让 Renderer 直接读取 Excel 或持有可任意访问的文件能力；
- 任务队列应直接消费 M1 的稳定 `ImportRow`，不得按数组下标重新关联原行；
- 已有译文列只作为输入状态，不得被自动覆盖；
- 在线翻译仍未启用；未命中术语或缓存的内容进入人工填写；
- M2 需加入任务、精确缓存和最小恢复，但 SQLite 仍只能由 Python Worker 读写；
- 翻译器版本、保护规则版本和用户修改必须为 M3 审核与导出保留可追溯信息。
