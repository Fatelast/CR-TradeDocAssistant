# 中俄贸易文件助手｜M2 离线翻译任务知识快照

## 阶段结论

M2 已完成从 M1 稳定 Excel 行到可恢复翻译任务的本地闭环：

```text
可信工作簿会话与列配置
→ Worker 重新构建稳定行映射
→ SQLite 保存任务和逐行状态
→ 精确缓存优先、术语库次之
→ 未命中内容进入人工填写
→ 用户逐行确认，可选择写入精确缓存
→ 重启后恢复未完成任务
```

当前没有在线翻译或本地大模型。术语库和缓存只产生“候选译文”，必须经用户确认；已有译文直接标为已完成，且不会被自动覆盖。

## 核心实现

- Python Worker 是 SQLite 的唯一读写者，Electron Renderer 不接触数据库或真实文件路径；
- Main 创建任务时把临时 `workbookId` 解析为可信路径，Worker 再次读取 Excel 并建立任务行；
- 每行持续保存原 Excel 行号、源/目标/箱号单元格坐标、原文、候选来源、译文、错误码和用户修改标记；
- 处理采用同步小批次请求，默认每批 50 行、上限 200 行；暂停在当前批次完成后生效；
- 精确缓存键包含原文、语言、翻译器、术语库版本和保护规则版本，避免规则升级后误用旧结果；
- 用户修改只在明确点击“确认并加入缓存”后写入精确缓存，不自动学习。

## 数据模型与状态

SQLite schema 版本为 `1`，包含：

| 表 | 用途 |
|---|---|
| `app_meta` | schema 与术语库版本 |
| `tasks` | 文件、列配置、翻译器版本、任务状态与时间 |
| `task_rows` | 稳定 Excel 坐标、候选、译文、状态和错误 |
| `glossary_terms` | 本地俄中术语 |
| `translation_cache` | 带版本维度的精确翻译缓存 |

任务状态：

```text
draft → running → awaiting_manual → completed
           ↘ paused → running
任意未完成状态 → cancelled
```

行状态为 `pending`、`candidate`、`needs_manual`、`completed`、`failed` 或 `ignored`。候选行不会计入已确认进度。

## 保护规则

翻译/匹配前会保护 URL、邮箱、箱号、订单类编号、日期、币种金额、型号、单位和数字。保护片段使用带序号占位符，恢复后逐一校验；缺失、重复或残留占位符会返回 `TOKEN_RESTORE_FAILED`，不得静默确认。

当前保护规则版本为 `1`，翻译器标识为 `glossary-manual-v1`。

## 默认边界

| 项目 | M2 默认值 |
|---|---:|
| 批次大小 | 50 行 |
| 单批上限 | 200 行 |
| 精确缓存保留 | 180 天 |
| 自动翻译 | 不启用 |
| 已有译文 | 保留并标为已完成 |
| 缓存/术语命中 | 候选，必须人工确认 |
| 未命中内容 | 待人工填写 |

任务与历史的 90 天自动清理、术语导入导出和设置页仍属于 M4；M2 只建立最小可恢复持久化基础。

## M3 继续开发时的约束

- 审核与导出必须使用 `taskId + rowId + Excel 坐标` 关联，不得按当前数组顺序回填；
- 只有 `completed` 或明确 `ignored` 的行可以进入导出决策；
- 导出前必须重新确认源文件身份与风险等级，且不得覆盖原文件；
- 目标列不存在时，只能追加到数据区右侧；
- M3 不得绕过 `TOKEN_RESTORE_FAILED` 或其他失败状态强行写回；
- 在线翻译仍未获准，若要引入必须另行确认费用、数据外发和凭据管理边界。
