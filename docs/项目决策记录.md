## DR-012｜M1 活动工作簿与只读解析边界

- **日期**：2026-07-30
- **状态**：已实施
- **决策**：Main 同时只维护一个活动工作簿会话；文件路径由 Main/Preload 获取，后续预览和数据行请求只使用临时 `workbookId`。Worker 仅以只读方式解析 Excel，不计算公式、不保存或修改原文件。
- **原因**：收紧 Renderer 的本地文件能力，并避免 M1 在解析阶段引入写回损坏和多文件状态混淆。
- **影响**：更换文件或重启应用会使旧会话失效；M2 必须直接消费 M1 生成的稳定行映射，不得重新按数组位置关联原行。

## DR-013｜M2 离线翻译、持久化与批次边界

- **日期**：2026-07-30
- **状态**：已实施
- **决策**：M2 不接入在线翻译或本地模型，采用“精确缓存 → 本地术语 → 人工填写”流程；缓存和术语命中只产生待确认候选。Python Worker 独占 SQLite，任务按默认 50 行、最多 200 行同步批次处理，暂停在当前批次完成后生效。
- **原因**：在没有外部翻译服务费用、数据外发和凭据管理方案前，先交付可审计、可恢复、不会自动猜测的本地工作流；小批次足以满足当前 5,000 行边界内的暂停与恢复，不需要引入后台队列和并发数据库写入。
- **影响**：任意未命中句子都需要人工填写；已有译文不覆盖；术语/缓存候选需人工确认；任务创建后可依靠 `taskId` 跨应用重启恢复。M4 仍需补任务 90 天清理、术语导入导出、历史与设置管理。

## DR-014｜M3 源文件身份、审核状态与安全导出边界

- **日期**：2026-07-30
- **状态**：已实施
- **决策**：任务创建时保存源文件 SHA-256、大小、修改时间和风险快照；只有全部任务行为 `completed` 或 `ignored` 时才允许导出。导出前重新校验源文件指纹和工作簿风险，受限文件不提供绕过。Renderer 只提交 `taskId`，输出路径由 Main 的原生另存为对话框产生；Worker 禁止覆盖原文件或已存在文件，先写同目录临时文件，重开逐格验证后再生成最终 `.xlsx` 副本。
- **原因**：M3 第一次引入文件写回。若任务创建后源文件被替换、界面可伪造任意输出路径，或保存成功却没有验证内容，都会造成错行、覆盖和不可恢复的业务文件风险。内容指纹、权限分层和验证后落盘可以在不引入复杂版本管理的前提下封闭这些风险。
- **影响**：M2 旧任务若缺少源文件指纹，必须重新导入后才能导出；任意候选、待人工或失败行都会阻止导出；忽略行保持原值；高风险 Excel 仍只允许受限预览。M4 可增加导出历史和设置，但不得放宽上述安全边界。

## DR-015｜M4 本地历史、术语交换与固定保留策略

- **日期**：2026-07-31
- **状态**：已实施
- **决策**：SQLite 升级至 schema v3；每次导出独立记录 `pending/completed/recovered/failed` 状态。历史重执行始终创建新任务，历史硬删除只删除数据库记录。术语交换只使用标准 `.xlsx`，设置只导出 JSON，不提供 SQLite 整库恢复。终态任务、精确缓存和应用日志分别固定保留 90、180、30 天，并通过预览后的修订哈希阻止过期确认。
- **原因**：M4 的核心是让离线工作台可长期维护，同时不能把“方便清理/恢复”演变成业务 Excel 被误删、任意路径访问或数据库恢复覆盖。强类型设置、原生路径选择、文件指纹、修订哈希和固定保留期可以在不引入账户、云服务和后台队列的情况下封闭主要风险。
- **影响**：Renderer 不能提交术语导入、导出、历史打开或设置导出的任意路径；默认输出目录只能沿用已保存值、清空或采用本次原生选择结果。运行中任务不能删除，任何源文件与导出 Excel 均不在自动或手动清理范围。在线翻译、数据库整库备份恢复继续延后。

## DR-016｜M5 Worker 冻结与 Windows 内测发布

- **日期**：2026-07-31
- **状态**：工程实现完成，外部验收待完成
- **决策**：Worker 使用 PyInstaller `onedir + console`，生产环境只执行 `resources/worker/rus-trade-worker.exe`；桌面端使用 electron-builder、ASAR 和 NSIS x64 当前用户安装，卸载默认保留 AppData。内测版为 `0.6.0-beta.1`，暂不签名、不自动更新；Windows 10/11、Excel/WPS、schema 数据升级和脱敏真实文件全部通过后再提升为 `1.0.0`。
- **原因**：`onedir` 保留稳定标准流并减少单文件解压和误报风险；生产路径不回退系统 Python，可以满足无开发环境运行和最小权限边界。Beta 与正式版本分离，避免把“能构建”误判为“已通过真实环境发布验收”。
- **影响**：发布构建必须携带完整 Worker 目录、应用图标和第三方许可，并生成 SHA-256；安装、升级和卸载不得清空 SQLite 数据或业务 Excel。代码签名证书、真实样本脱敏和多环境人工验收仍属于外部成本。
